# Evaluation and failure analysis

I separate observed deterministic results from unmeasured model and practitioner performance. The available evidence supports a working, narrow prototype; it does not establish production reliability.

## Executed checks

- **77 Python tests passed** on Python 3.12.14. They cover exact money, threshold boundaries, independent rational-arithmetic comparison over 120 randomized portfolios, accounting invariants, source/rule tampering, invented evidence, invalid coordinates, malformed objects, date/version conflicts, credits, HTML/CSV escaping, caching, proposals, review, audit integrity and HTTP controls.
- **10/10 synthetic acceptance packets passed.** Seven return the expected exact base; three correctly withhold it. The expected values in `examples/cases.json` are explicit reference outcomes, not generated by the production calculator.
- **Mock LLM tests passed:** valid JSON-schema proposals, one repair, bounded failure, unavailable service, missing credentials, oversized context, exact quotes and no automatic approval. These are adapter behavior tests, not measurements of a model's accuracy.
- JavaScript syntax passed `node --check borrowcheck/static/app.js`.
- CLI demo, extraction, exports and loopback HTTP integration were exercised. GitHub Actions is configured for Python 3.11/3.12/3.13; a configuration file is not evidence that remote CI has run.

Run the evidence again:

```bash
python -m unittest discover -s tests -v
python -m borrowcheck evaluate --out outputs/evaluation.json
python tools/benchmark.py --invoices 100000 --repeats 3 --out outputs/benchmark.json
```

## Measured efficiency

[The benchmark record](benchmark.json) contains three timings for 100,000 invoices and 2,000 debtors: **0.414, 0.400 and 0.396 seconds**, median **0.400 seconds**, approximately **250,089 invoices/second** in this environment. The engine performs two invoice passes and debtor aggregation. Arbitrary-precision integers avoid monetary floating-point error.

This measurement includes construction of the full calculation result but excludes fixture construction, CSV parsing, source validation, PDF extraction, model/network time, UI rendering and disk export. It is a single-machine microbenchmark, with no concurrent production load or memory profile. Do not convert it into an end-to-end service-level guarantee. O(n + d) retained detail also means memory grows with the output; million-row UI tables need pagination.

## Observed and designed failures

**A correct quote can support a wrong proposed number.** The adversarial test changes the extracted advance from 80% to 81% but retains the genuine 80% quote. Structural/evidence validation accepts the proposed pair. This is an intentionally documented failure of semantic assurance, not a successful extraction. A qualified reviewer must reject it before installation. An LLM cannot attest that it found every relevant exception.

**Document completeness remains external.** Hashes detect changed bytes against a manifest. They cannot discover an undisclosed waiver or prove invoice authenticity. A fabricated but internally consistent ledger and a false completeness attestation may pass.

**The offline parser fails outside its narrow template.** Multiple matching clauses or missing expected wording cause abstention. It is useful for a reproducible demonstration, not evidence of general contract understanding. The live model adapter has not been evaluated against independent labels or an API-backed run.

**Prompt injection detection is incomplete.** The tenth fixture contains an explicit phrase caught by a heuristic. Paraphrased attacks may evade it. The model's lack of installation/payment authority and human review are the substantive controls.

**Local review has no authenticated identity.** The supplied name is not verified. Hash chains detect edits without recomputation, but a file administrator can rewrite the whole chain or delete its tail. Production needs external anchoring and signed approvals.

**PDF/OCR coverage is limited.** Native text extraction is implemented, but the acceptance corpus uses TXT and CSV. Scanned documents block because OCR is absent. Negation loss and malformed tables remain unmeasured failure modes. PDF coordinate behavior needs a separately labelled corpus before reliance.

During implementation, checks were corrected to bind control amounts to their unique cited USD literal, validate stored line/PDF coordinates against source coordinates, reject malformed nested objects, and keep cached proposals unapproved. Regression tests exercise those corrections.

## Browser verification status

The optional Playwright smoke script checks the worked amount, source highlighting, ten-case screen, blocked review, audit signoff, mobile overflow and console errors. It could **not** be executed here: Chromium was unavailable and its download returned a “Site Unavailable” HTML page. I therefore do not claim browser-rendered visual verification. HTTP integration tests and JavaScript syntax checks passed.

With Node.js and browser-download access:

```bash
npm install --ignore-scripts
npx playwright install chromium
npm run test:ui
```

The script starts and stops its own local server, uses a temporary audit database, and writes screenshots and results under `outputs/ui/`. Node/Playwright are optional development tools, not runtime requirements.

## Next validation gate

Before a pilot I would obtain independently labelled contracts/packets, three analyst walkthroughs, and a spreadsheet comparison on at least 30 unseen synthetic cases. Measure false-ready results, abstentions, clause omission, review minutes, extraction cost and maintenance cost. Require cent-exact finance and detection of every seeded release blocker. The proposed 45-minute review target is a hypothesis, not an achieved outcome. Live LLM evaluation and real practitioner validation remain open.
